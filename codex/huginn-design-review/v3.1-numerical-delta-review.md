## Original findings, individually

1. **Gold prefill, batch aggregation and tokenization: computation repaired; admission needs the small cross-arm fix.** `gold_sequence_ids` and `arc_batch` use the same context tokenization followed by separately tokenized continuation (`huginn_relax_eval.py:377–404`). `fixed_spectrum --arc-ids batch` passes those IDs to `setup_ids` and records their hash (`explore_latent_loop.py:881–897,908–982`). The mask is one on real positions and zero on right-padding; both the per-row numerator and denominator multiply by it (`huginn_relax_eval.py:162–169`). Under the existing causal, per-sequence recurrence premise, later padding and other batch rows do not change the mathematical real-position gold prefill. This is not a claim of bit-identical float32/bfloat16 trajectories or identical initial gold states between single-sequence and batched runs. The design now expressly makes the outcome a gold-conditioned finite-budget association.

   The remaining gap is `huginn_arc_analysis.py:358–360`: `table[(q, lams[0])]` alone supplies the hash. A nonbaseline row with a different or missing hash can still contribute its residual. Require a nonempty hash for every `(q, arm)` and equality to the same question spectrum; refuse or consistently disqualify the question according to the frozen admission policy. Add a source-level regression for a changed/missing nonbaseline hash. No extra spectrum computation is implied.

2. **Residual clock: closed.** The trace records `R(s_k)` before the update while readout receives `s_(k+1)`; the 32nd trace entry is `R(s_31)`. The new constant/comment, recorded clock and design endpoint agree (`huginn_relax_eval.py:163,171–172,488–490`; `huginn_arc_analysis.py:259–260,290`; design:86–89). The claim is no longer mislabeled as a residual at `s_32`.

3. **Partial ARPACK spectrum: closed at the narrowed feature scope.** The design explicitly calls the union an estimated Ritz feature, discloses possible omitted shifted dominant modes, and distinguishes detected instability from absence of detection (design:73–80). Admission requires a nonempty finite union; the result retains each question's ARPACK flags/count (`analysis:263–277,361–364`). The float32 operator wrapped in a float64 SciPy interface remains approximate, and no full spectral completeness or rigorous stability is inferred. This is adequate for the specified held-out association; a full-spectrum proof is not required. The synthetic omitted-mode counterexample is present in the test source; I did not execute it.

4. **bfloat16 floor and finite-budget interpretation: closed.** The difference is now formed as `out.float() - x.float()` before its norm, instead of subtracting in bfloat16 (`relax_eval:165–169`). The recurrence remains bfloat16, as disclosed. The primary uses the original nonnegative gold residual without a log/clamp, with standard Spearman tie ranks (`analysis:289–290,298–308,330–331`). The design calls this a finite-budget endpoint, not an asymptotic contraction-rate estimate (86–89). Nonnormality, transients and initial amplitudes therefore remain interpretation limits, not hidden numerical guarantees.

5. **Exact relaxation theorem: bounded, with nonblocking legacy wording still outstanding.** For a differentiable real map, the affine multiplier formula is valid at a fixed point for nonzero relaxation; strict stability for sufficiently small positive lambda additionally requires every `Re(mu) < 1`. The unchanged `stability_interval` docstring still says the map “always contracts” at the small-lambda end (`analysis:178–180`), and its finite grid can clip an endpoint. This does not gate the new primary: `item_records` carries `lam_up`, but `item_statistic` uses only the estimated radius and residual, and the descriptive detected-mode counts compare that radius with one. Clean up the legacy docstring/the introductory exact-theory wording when editing prose; do not describe its grid endpoint as a certified boundary. No additional experiment or proof condition is requested.

6. **Pinned revision: closed at source level.** Both model and tokenizer loads explicitly receive Huginn revision `bb6621b65e90b6a4b9b29ef88dc83866d450470c`; the latent evaluator uses the same revision table. This review verifies loader arguments, not downloaded artifact contents.

## Trace compatibility and remaining limits

The tuple changed from two to three fields. Within the supplied ten-file bundle, `arc()` is the only production caller enabling `Relaxed.trace`, and it reads fields by index `[0]`/`[2]`. `convergence()` constructs independent native/step lists and does not unpack this tuple. The exported development tools consume saved JSON, not the tuple. Thus no source-confirmed tuple-length regression was found. The new tiny tests visibly cover per-row versus aggregate residuals and input/output clock; no test was run in this review.

The two numerical pipelines still intentionally differ in precision and execution arrangement. Shared gold IDs and masking repair the structural prefill mismatch; they do not establish exact equality of implemented floating maps. The revised association wording is appropriately limited. The separate statistical reviewer owns cohort/undefined-draw/B-margin conclusions. Once the cross-arm hash gate is repaired and source-reviewed, I have no remaining numerical blocker to freezing this finite design.

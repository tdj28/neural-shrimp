## Exact map and source admission

The external candidate-definition file is authenticated by an independently
supplied file SHA256. Its schema, intended-final-box role, all eight exact
896-coordinate centres, eight positive exact dyadic radii and map declaration
are required. Existing prototype schemas/roles are refused. Centre-selection
history is retained as provenance; derivative validity depends on the declared
exact domain, not on which refinement method selected its centres.

The map declaration is recomputed from the current independently pinned assets,
full prefix IDs, state/vocabulary/layer dimensions, steering layer 12 and exact
binary64 alpha/log10-temperature ratios. The temperature and rotary conventions
match the reviewed exact-real evaluator. Full-vocabulary expected-embedding
readout and exact stored binary checkpoint constants are explicit. The current
loader independently checks asset bytes and supplies model config, weights and
steering vector; the driver then checks architectural scope and uses private
read-only array views without mutating them.

The evaluator hash is a canonical **11-file source bundle**, including this
driver, all inherited transformer/Jet/linear/readout/cache code, domain/collector/
gate helpers and the independent pinned checkpoint loader. The bundle contents
must equal the plan's explicit path-to-hash map. Backend hash is independently
recomputed from Python, NumPy, Torch, python-flint, FLINT, precision and threads.
Source snapshots and successful receipts still need external authentication:
matching metadata or a source hash alone does not prove correct evaluation.

The unchanged cache reader checks exact parameters, prefix, assets, precision,
real-constant conventions, receiving object construction and required cache/
input/graph artifact hashes. It is not a whole-inventory audit of every unused
upstream artifact. The concrete run must preserve the already independently
audited complete prefix receipt/source chain as its trust anchor. New prefix
sources would require their own independent admission and mathematical review.

## Live domain and derivative directions

Both global nominal-domain hashes are computed from the same canonical exact
dyadic data: the phase-domain canonical-JSON convention and the shooting-gate
labeled-stream convention. They are not equated. Exact long-mantissa centres
remain exact when hashed even if they exceed derivative precision.

Domain construction includes lower-precision centre-rounding error in the
receiver radius. Crucially, the progress hook captures the actual live Jet
values **immediately before decoder layer 0**, after all scalar construction.
It verifies all original live endpoints contain the assigned nominal phase box,
then saves their exact records/hash before any decoder operation. The full live
tangent matrix must match the saved positive basis directions exactly, including
zeros. There is no midpoint projection or reliance on an earlier, narrower
serialized precursor.

The plan admits one global phase and one aligned contiguous block of 64 columns;
14 such blocks cover 896 directions when later fully assembled. The output
retains all 896 primal balls and all 896 x 64 signed derivative balls, with
finite/nonnegative-radius gates and the collector's exact field layout. The
collector additionally enforces full multi-phase coverage, no duplicate columns,
raw endpoint containment and original-primal consistency. A completed shard is
not sufficient by itself to call that full collector successfully.

## Execution evidence, label witness and failures

All 24 decoder start/end events must interleave in order. Both full-vocabulary
head passes must contain exactly the expected ordered 1024-token chunks, without
gaps, duplicate chunks or early head evaluation. Returned enclosures are saved
before later label bookkeeping can reject the run. A failed/partial shard file
must never be admitted just because it exists; the future adapter must require
the matching successful status and authenticated complete receipt.

The already-computed head diagnostic is retained and bound to design, map,
phase and original live input hash. It records all vocabulary competitors and
requires exact extrema, a margin enclosure containing their exact difference,
and a strict-positive flag consistent with the original margin lower endpoint.
This preserves an optional label witness on the actual receiver box. It does not
identify an orbit or replace existence, primitivity or attraction gates, and no
expected token ID is hardcoded.

The driver enforces fresh owned output, immutable input locations and a fixed
CPU1/nice10/18 GiB/3600-second plan. The launcher must enforce memory/time limits
and retain timeout receipts. Python exceptions retain prior domain, live input,
events and any completed full output. Every status keeps `certificate_passed`
false. No additional target run was authorized or performed by this review.

## Independent validation

Independently reran the driver, collector, phase-domain and streamed-head suites:
**198 tests passed in 1.98 seconds**, CPU1, no checkpoint data. This includes
strict map/assets/backend/source-bundle admission, exact high-precision centres,
live endpoint/tangent refusal, collector interoperability, layer/head coverage,
finite/full output gates, label-witness consistency, persistence on failure,
mocked whole-driver execution and isolated Python import.

An additional independent integration check used the actual inherited arithmetic
on a deterministic **synthetic** two-layer, four-state, seven-token transformer.
Four two-column shards over two boxes passed the live capture, both head passes,
label bookkeeping and complete collector assembly. All 32 assembled Jacobian
entries overlap a separate four-direction `BallQwenJet` reference on the same
boxes. The final-source check took 0.112 seconds and used no pretrained weights.
It verifies orchestration, not target-scale runtime, wrapping or proof success.

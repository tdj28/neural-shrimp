# Bounded parallel point-pass infrastructure

2026-10-13 UTC. Implementation and synthetic process tests only; no target model execution or concrete plan selection.

Source `parallel_phase_pass.py` SHA256 `2cdc3afd9e73d95857941034420d279db7f44b5177b82131cf5f1a44de6d2c43`; tests `test_codex_llm_parallel_phase_pass.py` SHA256 `5c5a2686b05c1cfa160f5735bc32761a183a740078806e02b20d94a7df3500e1`.

`run_parallel_pass(request_path, request_sha256, candidate_directory, *, deadline, max_workers=4, per_worker_timeout=600, aggregate_rss_bytes=32*GiB, minimum_available_bytes=12*GiB, worker_path=None)` uses an absolute monotonic deadline. The optional worker path selects the immutable source snapshot; production defaults to the sibling `phase_point.py`. Its bytes must match the worker hash in the externally pinned original request. The complete evaluator bundle and this controller must additionally be authenticated by the outer committed plan. This controller authenticates lifecycle and bytes; the unchanged worker authenticates the model and arithmetic request; a later independent audit checks the actual scientific endpoints.

Exactly eight global phases are scheduled. Four CPU1 worker slots are fixed, each with a wall allowance at most 600 seconds. Every launch requires at least the frozen 600-second remaining shared reserve, even if a caller supplies a smaller worker timeout. Insufficient reserve leaves explicit unstarted phases; it never extends the deadline. A fresh candidate layout and all phase/controller paths are checked before any launch. Existing completed-attempt receipts and existing phase directories prevent reuse. The original request is hashed from the exact bytes subsequently parsed, checked again before each launch and at completion, and copied by the workers. Workers may finish in any order; the successful pass receipt orders all eight phases canonically and requires every exit/status/source/map/backend/output hash gate.

The parent uses only the standard library and never loads a model. Each isolated `python -I -B` bootstrap sets CPU1 environment controls, disables GPU/network model fetching, preserves any stricter inherited limits, caps address space at 18 GiB and CPU time at the rounded wall allowance plus one second, then executes the pinned worker in the same PID. It records the actual limits and process identity. Linux PDEATHSIG=SIGKILL is armed before worker execution and checked against both parent PID and start time before/after arming. This protects the direct worker against abrupt controller death; **the reviewed worker must not spawn descendants**. Normal interruption/failure cleanup also signals verified owned process groups. An unexpected surviving descendant invalidates success and is terminated. PID/start-time checks prevent signalling a reused PID. Termination signals are blocked only across Popen and ownership registration, then unblocked in the bootstrap before entering the worker.

The controller samples its own RSS plus descendant/group RSS conservatively, including shared pages once per process. It records the peak and aborts at the requested limit (at most 32 GiB) or loss of the requested available-memory headroom (at least 12 GiB). This is **not a hard aggregate cgroup memory limit**. Other agents' processes are never killed. Each owned group receives SIGTERM, shares a two-second grace interval, then SIGKILL if needed; another shared two-second interval bounds reaping. The root launcher must leave its ordinary ten-second termination grace for controller cleanup. SIGKILL cannot preserve a final controller receipt, so the outer launcher remains responsible for its immutable incomplete-attempt receipt. The bootstrap guard still kills direct workers when the controller disappears abruptly.

Each launched phase gets a retained log, bootstrap identity/limits file and completed or partial receipt. Every existing worker artifact is hash-inventoried; full worker outputs are not discarded after a failed peer. Final evidence records unstarted phases, source and request hashes, sampled resource peaks, errors, leader exit codes and observed termination verification. A complete lifecycle result never asserts a certificate or that an endpoint audit was performed.

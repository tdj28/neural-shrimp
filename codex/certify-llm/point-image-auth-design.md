# Final exact-center image authentication: proposed small wrapper

2026-10-13 UTC. Design only; no implementation, final-domain selection, model evaluation or evidence admission is authorized by this note. The wrapper authenticates saved image enclosures and their exact inputs. It does not run an optimizer or a model and does not establish an orbit.

Inputs should be an externally SHA-pinned complete continuation-admission plan and an externally SHA-pinned final derivative-domain definition. The plan pins the completed parent receipt, exact capsule, independent review, all 16 unchanged runtime dependencies and the original prefix/seed inputs. The candidate definition supplies canonical exact center records, strictly positive exact radii, the final-box role and complete derivative-map identity. Trust anchors must come from the frozen reviewed design, not be extracted from the first convenient result.

Reuse the existing strict plan checks, current-source/audit binding, `load_bound_inputs` and `load_capsule` under the required 2048-bit point-admission context. These already authenticate complete immediate artifacts, source dependencies, original phase inputs/live states, full point outputs, exact zero tangents, decoder events, worker receipts and termination. The original A/B arrays are imported only as part of the unchanged input-authentication contract and must not be multiplied or passed to an optimizer. No update, proposal or dense inverse arithmetic is replayed. If a later focused importer avoids this unused array allocation, that is a separately reviewed change rather than a silent shortcut.

The complete capsule's **after** tuple is the selected final point tuple. Compare its every original canonical exact center record with the frozen derivative definition before numerical decoding. Reject radius-bearing nominal centers, noncanonical aliases, missing phases/coordinates, a different cyclic order, or any mismatch. Also bind each immediate raw worker input and successor to this same tuple through the existing admission. The derivative radii define the later boxes; they must not be treated as uncertainty in these point centers.

The point and derivative map metadata have different schemas and field names. Independently reconstruct both existing recipes using the same externally pinned checkpoint assets, prefix IDs, alpha and log-temperature dyadics, steering layer, architecture, all-vocabulary readout, exact-real temperature and rotary conventions. Then require each artifact to match its own reconstructed recipe. Do not equate their JSON hashes or normalize an untrusted map into the expected one. Their code paths—scalar BallQwen point evaluation and streamed Jet derivative evaluation—are distinct reviewed implementations of the same exact-real map. The wrapper must report this source-bound mathematical reliance rather than claim that metadata proves equivalence.

The 2048-bit point prefix and 1024-bit derivative prefix may differ as interval enclosures. Bind each separate successful-prefix provenance chain and require matching exact map/assets/constants, not identical cache hashes or interval widths. The previously reviewed prefix compatibility and receiving-array contract remains necessary. Point and derivative precision should be reported separately.

Return the original full point-image records, exact center records, raw file/receipt/capsule/source hashes, map cross-binding and an explicit provenance report. Any decoded Arb images must enclose the original serialized endpoints; no midpoint projection or radius loss is allowed. Recompute cyclic residuals against the exact successor only when requested by the gate caller, and hash the actual native vectors passed into the gates. The presence of a 2048-bit mantissa does not require 2048-bit context just to store an exact Arb point: tuple construction retains arbitrary exact midpoint data. Nonetheless every decode/pack round trip should check that center data remains exact and unchanged; subsequent arithmetic must remain outward-rounded at its declared precision.

Keep all `certificate_passed` flags false. Explicitly report that older archives were not rehashed by capsule admission and that the externally committed independent review is the trust anchor. The final proof orchestration separately needs identical exact center/radius/domain bindings across point images, full whole-box derivative coverage, root inclusion/contraction, primitive-period separation and attraction. Optional full-vocabulary labels are separate readout witnesses.

Synthetic controls should include a complete valid final tuple, altered center low bits below 1024-bit arithmetic resolution, cyclic phase permutation, equal-looking noncanonical centers, changed prefix/parameters/assets, source/backend mismatch, original image-radius loss, a partial/failed parent and a prototype derivative definition. No protected data or target model is needed to test those admission boundaries.

## Implemented wrapper and synthetic validation (2026-10-13)

`point_evidence.authenticate_points` now implements this limited read-only admission. The explicit arguments are the original plan and definition paths with externally frozen byte hashes; expected checkpoint assets, prefix IDs and backend version; the complete `point_evidence.SOURCES` digest map; and the separate externally pinned 1024-bit derivative backend and prefix contract. It returns exact native center vectors, native image balls that enclose every original serialized endpoint, and a provenance report. The candidate definition remains a proposed box domain, not an inclusion or orbit claim.

The complete local wrapper/reader dependency bundle is checked against external pins before using the capsule. Original canonical phase centers are compared using exact integer/Fraction data before any numerical decoder or legacy capsule admission. The unchanged complete upstream and capsule readers run at 2048 bits with one arithmetic thread inside a `try/finally`; the caller's precision and thread count are restored before the returned native image vectors are constructed. The base reader allocates its seven original numerical proposal arrays as part of authentication, then they are discarded without any matrix action or proposal calculation. Original plan, definition and capsule bytes are checked again at the end.

The 2048-bit point-prefix receipt must have completed successfully. Its exact inventory, captured graph bytes, map/constants/backend and precision are checked; cache construction and its original receiver installation remain source-bound obligations of the reviewed producer and capsule worker. The distinct 1024-bit derivative-prefix contract admits the independently reviewed successful prefix stage retained before the earlier box diagnostic failed. Its complete original cache records and prefix events are authenticated by the derivative evidence reader. No model is instantiated, neither prefix is recomputed, and the two prefix hashes or radii are never equated. The report distinguishes captured runtime-source verification from Git commit/blob verification, which it does not perform, and explicitly identifies the external older-capsule audit trust boundary.

New tests use the existing complete-capsule writers and synthetic worker fixture helpers, plus complete synthetic upstream seed and separate prefix attempts. They run the actual unchanged authentication readers; only dimensions, ownership paths and metadata are fixture-sized. They check successful full eight-phase admission at 64, 1024 and 2048-bit assembly contexts; retained nonzero image radii and exact centers; low-bit/phase-order/noncanonical/radius-bearing center rejection before decoding; and external byte/source/audit/backend/map/prefix/partial-parent/radius-loss refusals. No model, checkpoint, protected data or actual target attempt is read. The 24 new tests passed, and the combined point/capsule/derivative-evidence/continuation/domain suite passed all 207 tests. An initial combined command named a nonexistent test file and therefore ran no tests; the corrected named-file command produced the reported 207-pass result.

# Hardware ledger

Which hardware produced which result, so the work can be recreated on
similar machines. Generated by `tools/hardware_ledger.py` at commit `10bd10efc1f6`;
regenerate after new runs.

## Machines

- **Local host (`zeta`):** Intel(R) Core(TM) i9-14900K, 32 hardware threads; Linux.
- **Local GPU:** NVIDIA RTX 2000 Ada Generation, 16 GB, compute capability 8.9
  (sm_89), driver 580.178.04 (CUDA driver API 13.0). Float64 throughput is about
  1/64 of float32 on this card.
- **CUDA engine build:** `native/gdmap_cuda.cu` compiled with nvcc 12.4
  (`-O3 -std=c++17 -arch=sm_89 --fmad=false --ftz=false --prec-div=true
  --prec-sqrt=true`, host compiler g++-12), library SHA-256 prefix `062c5084efa7`;
  build receipt beside the library in the data store. The backend refuses other
  compute capabilities until qualified on them.
- **Software (current environment, from `uv.lock`):** Python 3.12.14, numpy 2.5.3,
  scipy 1.18.1, torch 2.14.1+cu130 (torch is used only for GPU-side
  bookkeeping in the rotation-map driver and for real-data experiments).
- **Rented GPUs (RunPod):**
  - Phase 0, 8 October 2026, pod v7jkobowrc6n4t: NVIDIA H100 NVL (95,830 MiB,
    compute capability 9.0, driver 570.133.20), image
    runpod/pytorch:2.4.0-py3.11-cuda12.4.1-devel-ubuntu22.04; engine built there
    with nvcc 12.4 (V12.4.131), g++-12 12.3.0, `-arch=sm_90`, mirror flags
    (fmad off); Python 3.12.15, numpy 2.5.3, scipy 1.18.1 (uv); torch 2.4.1+cu124
    for the benchmark. Receipts: `../neural-shrimp-data/runpod/phase0/`.
    Outcome: outputs are not bitwise identical to the sm_89 build (differences
    confined to chaotic and sensitive cells; status labels differ in 0.1% of
    S2-28011 cells and 1 of 1,024 S1R cells), see `docs/research-log.md`.
  - Language-model runs, 8 to 15 October 2026 (421 pods, 401 with retrieved results, 20 that ended
    without results; manifest regenerated 15 October 16:53 UTC after the last run): one entry per pod in
    `docs/manifests/runpod-runs.json`, generated by `tools/runpod_manifest.py` from the run receipts. Each entry has
    the GPU type and cloud, the code commit, the job set and its arguments, the wall time, the exit status and the
    upload and result hashes. GPU types: H100 NVL, H100 80GB HBM3, H100 PCIe, H200, H200 NVL, A100 SXM4 80GB,
    A100 80GB PCIe and RTX 4090. Driver and library versions are in each run's archived logs: `logs/hardware.txt`
    (nvidia-smi name, driver version, memory) inside its results archive, and the `versions` line of
    `runner-stdout.txt` (torch, CUDA, transformers, numpy, scipy). Example: the last run (FM5d) used an H100 NVL with
    driver 570.133.20, torch 2.14.1+cu126 and CUDA 12.6. Costs are kept out of both files.
  - Run RR (reset test, 15 October 2026): the local workstation GPU, NVIDIA RTX 2000 Ada Generation (16 GB), driver
    580.178.04, torch 2.14.1+cu130 (CUDA 13.0), transformers 5.19.0; the device name is also recorded in each run's
    `run.json` under `explore/llm-soft-loop/rr/`.
  Later rented runs are covered by the manifest; regenerate it after each run.
